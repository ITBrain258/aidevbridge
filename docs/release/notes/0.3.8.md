aidevbridge 0.3.8 says more precisely why something does not work, and fixes three faults: saving settings on Windows, a damaged key file, and a rare break in `known_hosts`.

- **Claude status:** when `claude agents --json` ends with an error code or answers with something that is not agent JSON, a session whose pane runs Claude now shows that reason instead of "no agent source is attached yet". Exit 127 says that `claude` was not found for SSH commands, usually because it is not on the search path the host sets for non-interactive SSH commands. Other sessions keep their reason.
- **Shell that prints on every SSH command:** if that text goes to standard output, **New session** is now disabled and says why, also through Ctrl+Shift+N and quick open. Before, tmux created the session, the app reported a failure, and no list could show the session. Remove the output from the shell startup file (for example `~/.bashrc` or `~/.zshenv`) and reload the sessions to lift the block. Messages on standard error only block nothing.
- **Damaged key file:** a damaged key without a passphrase was reported as a wrong passphrase. It now says the key file could not be read.
- **Windows:** when another program, such as a virus scanner, briefly holds the freshly written settings file, saving now retries for up to 310 ms instead of failing at once.
- **known_hosts:** after an unusual read error, a new entry could run into the last line of the file; it now starts on a line of its own.
- In the confirmation for **Remove** (host), the arrow keys stop at the first and last button, as in the confirmation for **Kill**. Before, they wrapped: the left arrow on **Cancel**, which has the focus when the bar opens, jumped to the red **Remove**.
