aidevbridge 0.3.8 says more precisely why something does not work, and fixes three faults around saving and reading keys.

- **Claude status:** when `claude agents --json` fails or answers with something that is not agent JSON, a session whose pane runs Claude now shows that reason instead of "no agent source is attached yet". Exit 127 says that `claude` was not found for SSH commands, usually because it is not on the search path the host sets for non-interactive SSH commands. Other sessions keep their reason.
- **Shell that prints on every SSH command:** on such a host **New session** is now disabled and says why, also through Ctrl+Shift+N and quick open. Before, tmux created the session, the app reported a failure, and no list could show the session. Remove the output from the shell startup file (for example `~/.bashrc` or `~/.zshenv`) and reload the sessions to lift the block.
- **Damaged key file:** a damaged key without a passphrase was reported as a wrong passphrase. It now says the key file could not be read.
- **Windows:** saving settings no longer fails when another program, such as a virus scanner, briefly holds the freshly written file.
- **known_hosts:** after an unusual read error, a new entry could run into the last line of the file; it now starts on a line of its own.
- In the confirmation for **Remove** (host), the arrow keys stop at the first and last button, as in the confirmation for **Kill**.
